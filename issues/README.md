# Issues

In-repository issue tracking, following the convention used in [`global-flood-hydrotectonic-model`](https://github.com/jdlongmire/global-flood-hydrotectonic-model).

- `open/` – live issues
- `resolved/` – closed issues, retained with their resolution

Naming: `I-NNNN-short-slug.md`

Each issue states the problem, why it is load-bearing for the programme rather than merely untidy, the resolution paths available, and current status. Issues that block a register entry name the entry, and the entry names the issue back.

These may be mirrored to GitHub issues for external contributors. The files here are the record of account.

## Workflow rule (adopted at v1.2)

Repository-side edits to the charter are confined to **mechanical fixes**: citation defects, ordering, cross-reference targets, dead links. Everything **substantive** is routed through an issue here for author decision and is not applied unilaterally.

The rule exists because the author revises from a local copy, so the repository would otherwise diverge on every revision. I-0007 is the worked example: three passages went missing in a revision, were tracked rather than silently reinstated, and were restored on direction.
