Both concern the same question: an explanatory model of the endogenous retrovirus record within a designist framework. They are run in parallel on purpose, to see which method makes a programme progress.

## Firewall

- **Shared freely:** primary data, data manifests, citation corrections.
- **Not shared before the comparison date:** models, criteria, registered predictions, auxiliary dispositions, verdicts.
- **Disclosure log:** each programme keeps one, recording anything that crosses, with date and bridge or repository commit. Programme A's log is in [`lines/genetics.md`](../lines/genetics.md#disclosure-log).
- **No double registration:** if both programmes register the same prediction, the earlier registration owns it and the other cites it.

## Rubric (fixed in advance, applied identically to both)

Each item is scored from each programme's own repository at the comparison date, citing commits.

| # | Measure | How scored |
|---|---|---|
| R1 | Corroborated use-novel facts | Count. Eligible only if novelty was marked at registration and the registration predates the evidence. |
| R2 | Failed registered predictions | Count, with the response to each. |
| R3 | Auxiliaries introduced after the anomaly that prompted them | Count by Lakatos's grades: ad hoc₁ (no excess content), ad hoc₂ (excess content not corroborated), ad hoc₃ (not from the positive heuristic). |
| R4 | Explanatory scope (McCullagh) | Datum classes accommodated, and datum classes carried as open anomalies, over a common data list fixed by the scorer before scoring. |
| R5 | Explanatory power (McCullagh) | Per datum class: does the model make the data more probable than its rival does? Qualitative, with reasons. |
| R6 | Each programme's own parity verdict | As stated by that programme at the date, under its own definition. The two definitions are themselves compared. |
| R7 | Disclosure events | Count and content of anything that crossed the firewall, and whether it was adopted. |
| R8 | Hard-core conformity | Any commitment of either programme in tension with its governing hard core, and how it is handled. |

## Scoring

- **Primary scorer:** an agent with no access to either programme's working sessions, given only the two repositories at pinned commits and this rubric.
- **Adjudication:** JD.
- **Reporting:** a single document, written to both programmes, publishing every item including those unfavourable to either.
